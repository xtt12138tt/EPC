项目概览：面向业务流程的 AI Agent

项目角色项目设计与工程实现
迭代周期2026.06 - 2026.08
主要场景内部报销提报与收款人核验
交付形态Skill、Web、浏览器执行器、分发包

核心工作

  • 将 EPC 业务规则拆成可维护的 Skill、费率表和费用说明模板。
  • 设计统一 JSON Schema，让 AI 解析、前端审核和浏览器执行共享同一份数据。
  • 实现 5000 前端批次工作台、草稿审核、状态管理和收款人差异处理。
  • 实现 Playwright 填报、截图、回读核验、暂停/继续和恢复提示。
  • 将当前版本拆成可分发的业务规则包、前端服务包和本地执行器包。

关键风险与设计取舍

  • 保证单一信息源：确认后的标准 JSON 是前端和执行器唯一读取的数据；其中的显式个人金额、小计等业务事实优先，费率表仅用于补全缺失信息或提示冲突，不得自动覆盖。
  • 避免金额填对、收款人填错：费用明细总额、收款人总额与 EPC 页面回读结果三次对账，任一差异都会暂停。
  • 避免同名误付：手机号精确匹配优先，姓名仅作补充；模糊候选必须人工关联，同名不同手机号直接阻断。
  • 避免自动化越过责任边界：AI 只生成草稿；第一页、收款人和最终提交保留人工闸门，并记录规则版本与确认结果。

问题：报销不是“把数字填进去”

01 · INPUT

输入不结构化

姓名与手机号可能粘连；玩家、接口人、兼职混在一起；金额列没有完整表头；备注中还会出现鸽子、代收和补测。

02 · RULES

金额需要业务拆分

玩家礼金、交通补贴、转介费、兼职场次费和餐补必须进入不同 EPC 类目，且收款人金额还要单独对账。

03 · RISK

自动化不能越权

涉及收款人和费用信息，系统必须能暂停、解释差异、保留人工确认，而不是让模型直接提交。

方案：规则驱动的 AI + 确定性执行

系统拆成“业务规则、AI 解析、前端审核、本地执行器”四层，统一使用标准 JSON 作为唯一事实源。

解析与校验：让 AI 输出可核对的业务结果

① 表格结构恢复

清理合并单元格、空行、中文标点和粘连文本
识别玩家 / 接口人 / 兼职等分段切换
从同一行提取姓名、11 位手机号、数量、金额和备注
保留原始字段，避免模型“补写”不存在的数据

② 规则与金额拆分

显式优先个人金额、单价、小计优先于费率表
双口径兼职场次费、补贴与实际收款分别计算
类目基础礼金、交通补贴、转介费、兼职、其他
假设时长、稀缺性或难度缺失时输出待确认项

③ 收款人双重确认

1手机号精确一致：自动匹配
2规范化姓名一致：自动匹配
3同手机号、不同姓名：提示确认
4同音/一字差异：只给模糊候选，人工关联
5同名不同手机号：高风险阻断，不自动填

可交接的三模块交付

01 · RULE PACK

业务规则包

Skill、费率表、类目映射、费用说明模板和批量协议，指导 AI 如何拆分和校验。

02 · CONTROL PANEL + AI

前端控制面板与 AI 服务

负责接收多种输入、调用规则完成解析，并提供单笔/批量录入、草稿审核、状态管理和收款人差异处理。

03 · EXECUTOR

本地 EPC 执行器

使用用户自己的 Edge 登录态填写 EPC、回读核验，并在高风险节点暂停等待确认。

结果：沉淀为可复用的 AI 工作流

将原本依赖人工经验的提报流程，沉淀为可追踪、可审核、可交接的系统能力；同时减少重复录入和反复核对，把人工时间留给业务判断与最终确认。

规则可维护

将人员分类、金额拆分、类目映射和费用说明固化为可维护 Skill。

数据可验证

费用明细总额与收款人金额独立对账，减少漏项和重复计算。

重复操作自动化

系统完成资料解析、费用拆分、页面填写与回读核验，人工聚焦异常处理和关键确认。

下一步规划：补齐真实使用中的两处痛点

01 · AI SERVICE

解析链路服务化

当前需要从前端保存 JSON，再手动交给 Codex 解析并导回。下一步将在权限允许后接入合规的 AI API / 内部模型服务，让前端直接提交资料并异步返回解析草稿与待确认项。

02 · AUTOMATION ADAPTER

EPC 执行器适配化

当前填写逻辑依赖页面元素与固定流程，EPC UI 更新后需要调整脚本。下一步将字段定位、页面步骤和校验规则抽成适配层，并增加填报前自检与页面变更提示。
